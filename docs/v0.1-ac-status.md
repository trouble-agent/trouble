answers the mechanical question (does every AC in the SPEC-INDEX §3.2 matrix have
a reference, and which test names it); this file answers the one that matters:
**which ACs the wave that shipped SPEC-10 + SPEC-12 + `cmd/*` actually closes, and
which are only half-built because their owning spec is a different branch.**

## What is proven by a running system, not by a package test

`tests/e2e/cli_smoke.sh` drives the two shipped binaries against a throwaway state
root and asserts 24 operator-visible facts, including: a stamped version triple, a
`config explain --json` dump with provenance for the full SPEC-10 §3.4 key set, the
T1..T5 topology rows, `install --check` writing nothing and refusing an unstamped
build with TROUBLE-LIFECYCLE-006 unless `--force`, a minted token whose plaintext
never appears in `token list` or in the 0600 file, `escalate` refusing with
TROUBLE-LIFECYCLE-016 when no channel is configured, the daemon booting and serving
`/health.json` unauthenticated on loopback while `/incidents` needs a token, a
URL-borne token being refused with 400, the checker exiting 0 against the live
daemon and 8 after it stops, and the drain writing the `stage="shutdown"`
heartbeat.

## Known gaps this branch does not close

1. **Sibling specs.** SPEC-04 (sentinel), SPEC-07 (research), SPEC-08 (flow),
   SPEC-09 (issues) and SPEC-11 (skills) are separate branches; `cmd/troubled`
   composes them the moment they land (the registry's `FileIssue`/`CreateTask`/
   `Comment` hooks and the ladder's `Outlets`/`Research` seams are the only places
   that change).
2. **The ingestion listener is validated but not served.** The bind preflight
   covers `ingest.bind` (including the advertised-host and proxy-mode refusals),
   and the daemon holds only the dashboard listener until SPEC-04 provides the
   handler.
3. **`units_test.go` does not run `systemd-analyze verify`.** The units are
   validated structurally (placeholders rendered, `ExecStart` present with only
   `--config`, `OnFailure=` present, install confined to a temp root); a real
   `systemd-analyze` pass is not part of the suite.
4. **The ETXTBSY regression test is absent.** SPEC-12 §6.2 asks for it; the lane
   removed the attempt because it needed a helper process and the package forbids
   `t.Skip`. `upgrade_test.go` still proves the rename-over path and that a park
   failure renames nothing.
5. **Per-project scoping.** `[[projects]]` is not resolved yet, so
   `dashboard.project_scope` is carried but `MaxProjects` is 0 (single tenant, the
   v0.1 shape) and the token/ingestion-key separation is enforced by grammar and
   by the mint-time refusal rather than by a configured key list.
